  4. DEPLOYMENT STEPS
═══════════════════════════════════════════════════════════════════════════════

Step 1: Create Render Service
  1. Go to https://dashboard.render.com
  2. New + → Web Service
  3. Connect michael-DDOG/chat-heist
  4. Paste environment variables from checklist above
  5. Create Web Service

Step 2: Wait for Initial Deploy
  • Takes 5-10 minutes
  • Monitor logs for errors
  • Should see: "✅ Server running on port 10000"

Step 3: Run Database Migrations
  In Render Shell tab:
  $ npm run migrate:deploy

Step 4: Set APP_BASE_URL
  1. Copy Render URL (e.g., https://chat-heist.onrender.com)
  2. Environment → APP_BASE_URL → Paste URL
  3. Save (auto-redeploys)

Step 5: Set Telegram Webhook
  Run LOCALLY (not in Render):
  $ npm run set:webhook

═══════════════════════════════════════════════════════════════════════════════
  5. POST-DEPLOY COMMAND
═══════════════════════════════════════════════════════════════════════════════

After first deploy, run this locally:

  npm run set:webhook

This command:
  • Reads APP_BASE_URL and TELEGRAM_BOT_TOKEN from your local .env
  • Sets webhook to https://your-app.onrender.com/telegram/webhook
  • Prints success/failure status
  • Shows webhook info (URL, pending updates, errors)

  7. TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Build fails:
  → Check Render logs for errors
  → Verify all files committed to GitHub

Database error:
  → Verify DATABASE_URL format (should have sslmode=require or none)
  → Check Supabase project is active

Redis error:
  → Verify UPSTASH_REDIS_REST_URL uses https://
  → Verify using REST token (not Redis password)

Webhook not working:
  → Re-run: npm run set:webhook
  → Check APP_BASE_URL has no trailing slash
  → Verify bot has inline mode enabled in @BotFather
